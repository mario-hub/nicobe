# NicoBE

MPC-BEで再生している録画に、NicoJKの実況コメントを重ねて表示するWindows用アプリです。タスクトレイに常駐し、起動中のMPC-BEを自動検出します。

付属の **NicoBE Encoder** は、TSをH.264／H.265／AV1のMP4またはMKVへ変換し、コメントの同期に必要な録画情報と、任意でコメント本体を保存します。コメントはMP4では元の本文・全属性と同期時刻を保持する形式、MKVではASS字幕として保存します。

録画・コメントの取得機能はありません。TVTest／NicoJKなどで保存したファイルを使用します。

## NicoBE

### 主な機能

- MPC-BEの再生位置、一時停止、シークに追従。複数のMPC-BEにも個別に対応。
- 起動時に既存ウィンドウを一度確認し、以後はWindowsの通知でMPC-BEを検出。毎秒のプロセス検索は行いません。
- MPC-BEがすべて終了すると、描画スレッド、GPU資源、コメント・文字キャッシュを破棄し、一度だけメモリを回収します。設定画面を閉じた後も、プレイヤーがなければ回収します。
- 映像の再生倍率を変更しても、流れるコメントの移動速度を維持。
- Direct3D 11／Direct2D／DirectWrite／DirectCompositionによるGPU描画。60 FPSを目標に動作。
- フォント、文字サイズ、行間、文字速度、時間調整、コメントの表示・非表示。
- NG ID／NGワード。再生位置付近のコメント一覧からの登録と手動入力。
- 録画情報を埋め込んだMP4／MKVへの対応。コメントも埋め込めば、元TSや外部ログなしで再生可能。
- MKVのASS字幕、動画と同じフォルダの外部ASSからコメントを再生。
- 録画中のTS／M2TS／MTSと、追記中のNicoJKコメントログに追従。

常駐中でも待機時のCPU負荷とメモリ使用量をできるだけ抑える設計です。プレイヤーがない間は定期的なプロセス検索やコメント描画を止め、不要なRAM・VRAMを解放します。待機へ移る際は、使っていないメモリページもWindowsへ返します。ランタイムやドライバーの内部領域は残るため、使用量がゼロになるわけではありません。

### 動作環境

- Windows 11 x64を推奨。[.NET 10のサポート対象Windows](https://github.com/dotnet/core/blob/main/release-notes/10.0/supported-os.md)が必要です。Windows 10はエディションごとにサポート状況が異なります。
- [.NET 10 Desktop Runtime](https://dotnet.microsoft.com/download/dotnet/10.0) x64。現在のビルドはランタイムを同梱していません。
- [MPC-BE](https://github.com/Aleksoid1978/MPC-BE)。通常の実行ファイル名 `mpc-be64.exe`／`mpc-be.exe` を自動検出します。
- Direct3D 11に対応するGPUとドライバー。ソフトウェア描画への自動切り替えはありません。
- TS再生時には、録画に対応するNicoJKのログ。
- NicoBEでMKVを読み込むには、配布フォルダ内の `mkv` フォルダをそのまま使用します。FFmpegの別途インストールやパス設定は不要です。
- MKVのコメント読み取りはASS／SSA字幕が対象です。bzip2圧縮された字幕には対応していません。
- Encoderには `ffmpeg.exe` と同じフォルダ内の `ffprobe.exe` が必要です。Encoderの基本設定からダウンロードできます。GPUエンコードには各方式に対応するGPU・ドライバー・FFmpegが必要です。

### 初回設定と使い方

1. 配布フォルダを展開します。Program Files配下では設定・ログをユーザーのLocalAppDataに保存し、それ以外では展開先に保存するため書き込める場所を選びます。フォルダ構成は維持してください。
2. 展開した製品フォルダにある `NicoBE.exe` を起動します。初回は設定画面が開き、NicoJKのログパスを指定する案内を表示します（例：`C:\TvTest\Plugins\NicoJK`）。
3. NicoJKログのパスに、`jk1`、`jk4`などのフォルダを含む親フォルダを指定します。
4. 必要ならスタートアップを有効にし、「反映して閉じる」を押します。
5. MPC-BEを自分で起動し、TSまたは対応するMP4／MKVを開きます。コメントはバックグラウンドで準備され、準備が終わると表示されます。開始時も直前10秒分から画面内に残るコメントを復元するため、準備中に再生位置が進んでも、冒頭のコメントを表示するためにシークする必要はありません。

埋め込みコメントやASSだけを使用する場合、NicoJKログパスは空欄で構いません。

ログフォルダの例：

```text
NicoJK/
├── jk1/
│   └── 1790000000.txt
└── jk4/
    └── 1790000000.txt
```

NicoBEはMPC-BEの起動や動画ファイルの受付を行いません。動画はMPC-BEで開き、秒送り・戻しと速度変更はNicoBEの操作パネルからも行えます。

### トレイと設定

「その他」タブには、アプリのバージョン・公開日、Webサイトを既定の外部ブラウザで開くボタン、利用コンポーネントのライセンスをまとめています。本文の改行は複数行で表示します。

- 左クリック：マウスポインターの左上付近に設定画面を開きます（初回の自動表示は画面中央）。
- 右クリック：「コメントを表示」「設定」「終了」を選べます。
- 終了してもMPC-BEの再生は継続します。
- スタートアップは設定を変更して保存したときに、現在のユーザーのWindows自動起動へ登録・解除します。
- 時間調整は正の値でコメントを早く、負の値で遅く表示します（−10～＋10秒）。
- シーク時は移動先の10秒前からコメントを再構成し、その時点で画面内に残るものを表示します。

「反映」は保存して接続中の全プレイヤーに適用し、設定画面を開いたままにします。「反映して閉じる」は同じ処理後に画面を閉じます。キャンセルしても、反映済みの設定は元に戻りません。

文字の太さは「細い（400）」「標準（700）」「太い（900）」から選べます。初期値は標準（700）です。フォントによって太さの違い方が異なります。

文字サイズ・文字速度の初期値は100％です。1920×1080の基準座標で文字サイズ48、文字速度360 px/秒に相当し、表示領域に合わせて拡大・縮小します。文字速度の設定範囲は50～300％です。行間は初期値30％、範囲0～100％です。既存の保存値は維持し、以前の行間100％超は100％へ、文字速度50％未満は50％へ読み込み時に調整します。「初期値に戻す」で新しい基準を選べます。

「カラー絵文字」は初期値オンです。Windows標準フォントにカラー情報のある絵文字を色付きで表示し、非対応の文字は従来の単色表示に戻します。オフにするとすべて単色表示です。対応する絵文字や見た目はWindowsのバージョンに依存します。この設定はNicoBEの再生表示に適用し、EncoderのASS出力には影響しません。

「長文コメントを加速」は初期値オンです。流れるコメントは本文の1文字目から、1文字につき設定速度の2％を加算し、50文字以上で最大100％増（2倍）になります。複数行は最も長い行を使い、絵文字・結合文字は表示上の1文字として数えます。オフでは文字数によらず設定速度で流れます。

配置時は実際の文字幅と速度から、先行コメントが左端へ完全に消えるまで追いつかない行を選びます。安全な空き行がなければコメント全体を省略し、表示を遅らせることはありません。上・下の固定コメントは加速せず、一時停止・シーク・再生倍率との独立性は維持します。

### 再生操作パネル

「操作パネルを表示」は初期値オンです。設定でオフにするとパネルを表示しません。映像領域の左下にある、パネルとほぼ同じ広さの範囲へマウスポインターを置くとパネルを表示します。パネルから離れると次のカーソル確認時（通常100ms以内）に隠れ、最小化時にも隠れます。コメントを非表示にしていても使えます。MPC-BEにフォーカスがなくても、他のウィンドウに隠れていない部分で表示・操作できます。秒送り・倍速変更では現在のアプリのフォーカスを維持し、歯車からは設定画面を前面に開きます。

- 秒送り・戻し：−30／−10／−5／＋5／＋10／＋30秒。
- 再生倍率：0.5／1.0／1.25／1.5／1.75／2.0／2.5倍。選択したボタンを強調表示します。
- 右上の歯車：設定画面を、そのプレイヤーの中央に開きます。
- 複数のMPC-BEでは、そのパネルに対応するプレイヤーだけを操作します。

MPC-BE本体で変更した倍率も、パネル表示中に0.5秒間隔でステータス表示から読み取り、強調表示へ反映します。選択肢にない倍率ではどのボタンも強調しません。一時停止中やステータスを取得できない間は、最後に確認できた倍率を維持します。日本語・英語の通常速度表示に対応し、その他の言語では倍率付き表示から再生中の文言を識別します。動画を切り替えると選択表示を解除します。表示領域が小さくボタンを収められない場合はパネルを表示しません。

### NG設定

NG設定タブには、最初に連携したプレイヤーの再生位置の前後5秒のログを表示します。一覧からIDやワードを登録でき、手動入力は1行1件です。NG IDは完全一致、NGワードは大文字・小文字を区別しない部分一致で判定します。「反映」または「反映して閉じる」で接続中のプレイヤーへ適用します。

### 録画中の追っかけ再生

MPC-BEで録画中のTS／M2TS／MTSを開くと、NicoBEは対応するNicoJKログの追記を自動で取り込みます。特別な切り替えは不要です。TSとログが他のプロセスから読み取れる状態で保存されている必要があります。映像の末尾延長・再生継続はMPC-BE側の動作に依存し、NicoBEが自動でプレイヤーを開き直したり再生操作を行うことはありません。録画開始直後に放送時刻などがまだ書かれていない場合は、追記を待って再試行します。

- 更新通知をまとめ、読み込みは最大で毎秒1回。通常はログの追記分だけを読み、書き込み途中のUTF-8文字やコメントは完成を待ちます。ログの切り替わり・作成・再作成にも対応します。
- 通知漏れへの対策として、TSを開いている間だけ30秒ごとに補助確認します。TSが伸びた場合は先頭の識別用データと末尾最大1 MiBから時刻を更新し、TS全体を読み直しません。
- 取り込んだコメントはファイルを閉じるまで全件保持します。通常の追加は末尾への追記、時刻が前後した追加は影響する範囲だけを結合し、毎回の全件ソートはしません。重複排除用の固定長SHA-256識別子も保持します。
- 追記で画面上のコメントを消しません。一時停止・シーク・時間調整・NG設定は従来どおりです。長い通信途絶後などの読み飛ばしは二分探索で行い、大量の過去コメントを1件ずつ処理しません。
- 別のファイルへの切り替え、ファイルを閉じる操作、プレイヤー終了時に監視を解除します。MPC-BEがない待機中にはログの監視・補助確認を行いません。

この追記対応はTS系ファイルと外部NicoJKログが対象です。生成途中のMP4／MKVやASSの追記監視は対象外です。NicoBE側の追記・一時停止・シークは擬似録画で確認しており、実際に録画中のTSを使ったMPC-BE側の末尾延長は未確認です。

### ASSとコメントの優先形式

- MKVは埋め込みASS／SSA字幕を読み込みます。NicoBE作成のトラックを優先し、その他はNicoJKの名前を持つトラックから調べ、流れるコメントを含むものを優先します。
- MP4／MKVと同じフォルダの `動画名.ass`、`動画名.*.ass`、Amatsukazeの `動画名-nicojk*.ass` も読み込めます。MP4にASSを格納する独自方式には対応せず、外部ASSを使用します。
- 一般設定の「コメントの優先形式」は、MP4の埋め込みオリジナルと外部ASSが両方ある場合に適用します。初期値はオリジナル優先。選んだ形式がなければもう一方を使用します。
- NicoBEが表示を始めると、MPC-BEで選択中の字幕が対応するコメントASSと識別できた場合に、その字幕をオフにします。コメント非表示・NicoBE終了時に元の選択へ戻します。字幕を手動変更した場合は、その選択を優先します。識別できない字幕は変更しません。

ASSからは表示時刻、本文、色、サイズ、流れる／上固定／下固定を読み込み、NicoBEのフォント・速度・配置で描画します。複雑な演出、描画命令、元の配置の完全再現は対象外です。ASSには投稿者IDを保存しないため、NG IDは使えません。NGワードは使用できます。ASSの時刻は動画の再生時刻なので、元TSの放送時刻は不要です。

## NicoBE Encoder

展開した製品フォルダにある `NicoBE.Encoder.exe` を起動します。「その他」タブでアプリのバージョン・公開日・ライセンスを確認し、「Webサイトを表示」で既定の外部ブラウザから説明ページを開けます。

1. **基本設定**：出力先、FFmpeg、コメント埋め込み用のNicoJKログフォルダを設定します。FFmpegの「ダウンロード」は確認後にダウンロード・検証・展開を行い、成功するとパスを保存します。配置は通常アプリの隣の `ffmpeg`、Program Files配下の場合だけ `%LOCALAPPDATA%\NicoBE\ffmpeg` です。その下は `ffmpeg-9.0.2-essentials_build/bin/ffmpeg.exe` のように配布元のバージョン名を残し、同じバージョンを再取得した場合だけフォルダ名に短い連番を付けます。
2. **エンコード設定**：保存形式（MP4／MKV）、映像形式、処理方式、解像度、フレームレート、画質、音声などを選びます。コメントの埋め込みと外部ASS保存は独立して選べます。
3. **操作**：TSを追加またはドロップし、「エンコード開始」を押します。複数ファイルは順番に処理します。

| 項目 | 選択肢 |
| --- | --- |
| 保存形式 | MP4／MKV |
| 映像形式 | H.264／H.265／AV1 |
| 処理方式 | CPU／NVIDIA NVENC／Intel QSV／AMD AMF |
| 解像度 | 1920×1080／1600×900／1280×720 |
| フレームレート | 24／30／60 fps（整数） |
| 画質 | 品質値／ビットレート指定 |
| 音声 | AAC 128／192／256 kbps、音声コピー |
| インターレース解除 | 自動／有効／無効 |
| コメントデータを格納する | オン／オフ。MP4はオリジナル形式、MKVはASS字幕。初期値オン |
| 外部ASSファイルを保存 | オン／オフ。動画と同名の外部ASSを保存。初期値オフ |
| コメント文字サイズ（ASSのみ） | 50～200％。初期値100％。外部ASS保存、またはMKVのコメント埋め込み時に有効 |

「エンコード設定」「基本設定」タブの右下にある「保存」で、両タブの設定をまとめて保存できます。エンコード開始時にも自動保存し、次回起動時に復元します。FFmpegやコメントログが未準備でも設定は保存でき、必要なファイルはエンコード開始時に確認します。入力ファイルの一覧は保存しません。初期値はH.265／NVENC、1920×1080、60 fps、インターレース解除「自動」、MP4、ビットレート指定1.5 Mbps、処理速度「標準」、2パス、AAC 128 kbps、コメント埋め込みオン、文字サイズ100％です。NVENCは設定したFFmpegで実際に初期化できるか確認し、使えない場合はCPUへ切り替えます。AV1ではQSV／AMFも初期化を確認し、利用できなければCPUへ切り替えます。CPUの品質指定では1パスになります。保存済みの設定があれば、それを復元します。

エンコード時のコメント文字サイズは、MKVの埋め込みASSと外部ASSに共通で適用します。ASSを出力しない場合はスライダーを無効にします。MP4の埋め込みコメントにはサイズ調整を加えず、NicoBEの再生設定で大きさを調整します（元コメントの大・小の指定は保持）。外部ASSを同時に出しても、MP4の埋め込みサイズには影響しません。ASSをNicoBEで再生する場合は、保存したサイズにNicoBE側の文字サイズ設定をさらに適用します。既存の動画は変更しません。

ASSの表示設定はNicoBEの製品初期値にそろえています。フォントはYu Gothic UI、太さ700、文字サイズ100％は基準座標で48、行間30％（行の間隔62.4）、基本速度360 px/秒、不透明度95％、固定コメントは5秒です。文字サイズスライダーは文字と行の間隔に適用します。流れるコメントは1文字につき2％加速し、50文字以上で最大2倍になります。複数行は最も長い行、絵文字・結合文字は表示上の1文字として数えます。追いつかない行へ配置し、空き行がない場合や同時表示70件を超える場合は省略します。配置できるコメントが1件もない場合はASSを保存せず、完了時に警告します。

Encoderは個人のNicoBE設定ファイルを読み込みません。MP4のオリジナルコメント保存には、これらの表示設定や混雑時の省略は適用しません。ASSの字幕再生では移動速度が動画の再生倍率に従い、Windowsのカラー絵文字表示も保存しません。NicoBEでASSを読み込む場合は、NicoBEの速度・配置・カラー絵文字設定で表示します。

「コメントデータを格納する」「外部ASSファイルを保存」は、両方オン・外部ASSだけ・両方オフも選べます。どちらかがオンなら対応するNicoJKログが必要です。外部ASSは動画と同名の `.ass` を同じフォルダに保存します。外部ASSで再生する場合は、動画とASSをセットで移動してください。既存の動画または同名ASSがある場合は、共通の連番を付けて上書きを避けます。ASSには投稿者IDがないため、NG IDは使えません。旧「MP4＋ASS」の保存設定は、MP4・埋め込みオフ・外部ASS保存へ移行します。

### CLIでエンコード

GUI版と同じフォルダの `NicoBE.Encoder.Cli.exe` を使います。エンコード処理はGUI版の `NicoBE.Encoder.dll` と共通です。CLIのEXEだけを別の場所へ移さず、配布フォルダ一式で使用してください。GUIは起動せず、1回につきTSを1本処理します。

```powershell
# 保存済み設定の出力先へ保存
.\NicoBE.Encoder.Cli.exe "D:\録画\番組.ts"

# 出力フォルダを指定
.\NicoBE.Encoder.Cli.exe "D:\録画\番組.ts" "D:\変換済み"

# ファイル名まで指定し、別の設定ファイルを使用
.\NicoBE.Encoder.Cli.exe "D:\録画\番組.ts" "D:\変換済み\番組.mkv" --settings "C:\設定\高画質.json"
```

| 項目 | 動作 |
| --- | --- |
| 引数 | 入力TSが必須。2つ目の出力先と `--settings <設定JSON>` は省略可能。TS／M2TS／MTSを受け付けます |
| 設定 | `--settings` 省略時はGUIと共通のデータ保存先の `encoder-settings.json`。なければアプリの初期値。GUIで保存したJSONやそのコピーを使えます |
| 出力先 | 2つ目の引数が最優先。省略時はJSONの `OutputFolder`、初期値はデータ保存先の `output`（保存先は下記参照） |
| フォルダ／ファイル | 既存ディレクトリはフォルダ扱い。それ以外は末尾が `.mp4`／`.mkv` ならファイル名、それ以外はフォルダ扱い。存在しない出力フォルダは作成します |
| 保存形式 | ファイル名指定時は拡張子をJSONの保存形式より優先。フォルダ指定時は設定のMP4／MKVを使用 |
| 同名出力 | 自動命名時はGUI同様に連番。ファイル名指定時は既存の動画・同名ASSがあればエラー。外部ASSは出力動画と同名で保存 |
| 相対パス | 引数のパスは実行時のカレントディレクトリ基準。JSON内のFFmpeg・ログ・出力先は、そのJSONの所在フォルダ基準 |
| 設定変更 | CLIは設定ファイルを保存・変更しません。明示した設定ファイルがない、不正なJSONや不明な項目がある場合はエラー |
| 準備 | FFmpeg／ffprobeと、コメント保存がオンならNicoJKログフォルダを事前に設定。CLIはダウンロードやダイアログ表示を行いません |
| 進捗・結果 | 工程・進捗・経過時間は標準エラーへ毎秒表示。完了した動画・経過時間・ログの場所は標準出力。警告・エラーは標準エラー |
| 中止 | Ctrl+C。生成途中の動画はGUIと同様に保持し、その場所を表示。入力TSは削除しません |

コメントの対象ログがない場合は動画を完成させ、最後に警告を表示します（ログフォルダ自体が未設定・存在しない場合は設定エラー）。GPUからCPUへの切り替え条件はGUI版と共通です。終了コードは `0`＝成功（警告を含む）、`1`＝処理失敗、`2`＝引数・設定・入力の不備、`130`＝中止です。PowerShellでは `$LASTEXITCODE`、バッチでは `%ERRORLEVEL%` で確認できます。

`--help`（または `-h`）で使い方、`--version` でバージョンを表示します。ハイフンで始まる入力名は `.\-番組.ts` のように指定するか、`--` の後に置きます。

### 日本語・英語の二重音声

TSの番組情報から日本語／英語の二重音声と判別できたAACは、自動で2トラックに分離します。MP4・MKVとも「日本語」「英語」の名前と言語情報を付け、日本語を既定にします。再生時はMPC-BEの音声メニューで切り替えられます。

各トラックには選択したAACビットレートを適用します。「音声をコピー」の場合も、分離する音声だけはAAC 128 kbpsで再圧縮します。その他の音声はコピーします。通常のステレオ音声は分離せず、二重音声の途中にあるステレオ区間は両方のトラックにステレオのまま保存します。

判別には録画の先頭・中間・末尾にある番組情報（EIT）と音声の識別情報（PMT）を使用します。番組情報が削除されているTS、言語や二重音声の情報が不明な音声は自動分離しません。

### AV1

映像形式でAV1を選べます。保存形式（MP4／MKV）、コメントデータの格納、外部ASS、文字サイズの仕様はH.264／H.265と共通です。初期値は引き続きH.265です。

| 処理方式 | 使用するAV1エンコーダー | 品質値の範囲 |
| --- | --- | --- |
| CPU | libaom-av1 | 0～63（CRF） |
| NVIDIA NVENC | av1_nvenc | 0～63（CQ。0は自動） |
| Intel QSV | av1_qsv | 1～51（ICQ） |
| AMD AMF | av1_amf | 0～255（QP） |

品質値は方式ごとに尺度が違い、同じ数値で同じ画質にはなりません。処理方式の変更で範囲外になった値は範囲内に調整します。CPUの処理速度は速度重視／標準／画質重視をlibaomのcpu-used 8／6／4に対応させます。AV1をCPUで処理する場合、録画の長さや設定によって時間がかかります。

GPU方式はAV1対応GPU・ドライバーと、そのエンコーダーを含むFFmpegが必要です。選択時と開始前に短い生成映像で初期化を確認し、使えない方式はCPUへ切り替えます。CPU用FFmpegにはlibaom-av1が必要です。エンコード途中のエラーでは自動再試行しません。QSV／AMFは対応機器での実動画エンコード確認は未実施です。

AV1でもCPUのビットレート指定とNVENCは1／2パスを選べます。CPUの品質指定、QSV、AMFは1パスに固定します。再生にはAV1に対応するMPC-BE／デコーダーが必要です。

### 1パス／2パス

- **CPU＋ビットレート指定**：1パス、または全編を解析してから本エンコードする2パス。
- **NVENC**：1パス、または各フレーム内での2段階処理（full-resolution multipass）。動画全体を2回読み込む方式ではありません。
- **CPU＋品質指定、QSV、AMF**：1パスのみ。選択欄を無効にします。

VBR／CBR、最大ビットレート、Bフレーム数の個別設定はありません。品質値の尺度は処理方式によって異なります。

### 出力と失敗時の扱い

- 出力先の初期値はEncoderのデータ保存先の `output`（通常は実行ファイルの隣）。元TSは削除しません。
- 出力名は元TSの拡張子を `.mp4`／`.mkv` に変えた名前です。コーデック・解像度などは付けません。同名の動画・ASSがある場合だけ ` (2)` などの連番を付けます。CLIでファイル名を指定した場合は、その名前を使用します。
- 行の「×」や「リストをクリア」は、一覧だけを変更します。
- 正常に完了したTSは順次リストから外れ、失敗・中止した項目は残ります。元TSは削除しません。
- 経過時間と進捗を表示し、失敗は一覧とエラー欄に表示します。結果・保存先・エラー・警告の文字は選択してCtrl+C、または右クリックの「コピー」で取得できます。詳細はEncoderのデータ保存先の `logs` に保存します。
- コメント保存がオンでも、対象コメントが0件・対象チャンネルのログなし・実況局の対応なしの場合は、コメントなしで動画を出力します。空のコメントデータやASSは作らず、録画情報は保存します。処理終了時に警告件数と対象ファイル・理由・保存先をまとめて表示し、処理ログにも記録します。正常完了として一覧から外し、後続の動画も処理します。
- NicoJKログの親フォルダの設定不備や読み取り権限などのエラーは、コメント0件として扱わずエラーを表示します。
- 失敗・中止時に生成済みの動画がある場合は、`_同期確認失敗_` または `_未完了_` を付けて残します。完成品とは区別してください。

### 保存形式と再生に必要なもの

| 動画の内容 | 再生時に必要なもの |
| --- | --- |
| MP4：録画情報とオリジナルコメントを埋め込み済み | MP4のみ |
| MKV：ASSコメントを埋め込み済み | MKV |
| MP4／MKV：録画情報のみ埋め込み済み | 動画と対応するNicoJKログ |
| MP4／MKV：対応する外部ASSあり | 動画とASS |
| 録画情報も対応ASSもない通常の動画 | 自動同期の対象外 |

エンコーダーはカットなしの変換を対象にしています。CMカット、速度変更、編集には対応しません。元TSを削除済みで、録画情報も対応ASSも残っていない動画は、ファイル名だけから正確な同期情報を復元できません。

MP4では録画情報とコメントを独自UUIDボックスに保存します。MKVでは録画情報を `NICOBE_RECORDING` タグ、コメントを `NicoBE Comments` というASS字幕トラックに保存します。コメント埋め込みがオフでも録画情報は保存します。他のソフトで再変換・再多重化すると失われる場合があります。

MKVのASSは通常の字幕対応プレイヤーでも表示できます。その場合の文字速度はプレイヤーの再生倍率に従います。NicoBEで表示するときは設定した文字速度を維持します。元TSの放送字幕、データ放送、チャプターはエンコード出力へ引き継ぎません。

## MP4ファイルフォーマット

NicoBE Comment Format **Version 1**。コメントの本文と全属性を保持し、動画に対する表示時刻だけをコメントごとに追加します。Position・Color・SizeScaleなどの表示用の数値は保存しません。旧形式への互換・移行処理はありません。

### MP4内の配置

MP4のトップレベルに、コメントと録画情報を別々の `uuid` ボックスとして格納します。コメントボックスだけで再生でき、録画情報は必須ではありません。どちらも0個または1個です。映像・音声トラックや字幕トラックではなく、動画への焼き付けも行いません。

| 項目名 | 説明 | NicoBEで参照しているか |
| --- | --- | --- |
| size | 4バイトの符号なしビッグエンディアン整数。ヘッダーを含むボックス全体のバイト数。通常のuuidでは24＋ペイロード長 | はい：構造解析 |
| type | ASCIIでuuid（4バイト） | はい：識別 |
| largesize | size=1の場合に続く8バイトの符号なしビッグエンディアン整数。この場合は32＋ペイロード長。size=0はファイル末尾まで | はい：読み取り対応。書き込みは通常サイズ |
| usertype：コメント | UUID 5077db8e-aaf4-174f-a59f-f650f165a0c3。16バイトの順序は5077DB8EAAF4174FA59FF650F165A0C3 | はい：コメント識別 |
| payload：コメント | gzipで圧縮したUTF-8 JSON。BOMなし | はい：展開・解析 |
| usertype：録画情報 | UUID b728b028-bab6-de44-979a-30eb28e71c5d。16バイトの順序はB728B028BAB6DE44979A30EB28E71C5D | はい：録画情報識別 |
| payload：録画情報 | 圧縮しないUTF-8 JSON。BOMなし | 条件付き：外部NicoJKログとの同期に使用 |

UUIDは上記の16進バイト列をその順序で使用してください。.NETのGuid.ToByteArray()の既定のバイト順で変換しないでください。ボックスは末尾以外に置いても読み取れます。NicoBE Encoderはエンコード中の一時ファイル末尾に追記し、読み戻しを確認してから完成ファイルとして公開します。

### コメントJSON

項目名の大文字・小文字を区別します。「必須」と記載した項目は省略・null不可。任意のChannelは省略またはnullで不明を表します。

| 項目名 | 説明 | NicoBEで参照しているか |
| --- | --- | --- |
| Version | 必須の整数。1 | はい：対応形式の確認 |
| Channel | 任意の文字列。NicoJKのjk番号（jkの後に1桁以上の数字）。例：jk4。特定の局を必須にせず、桁数制限や独自の番号変換を設けない | はい：局の識別情報。格納コメントの再生・同期には不要 |
| Comments | 必須の配列。空配列も有効。MediaSecondsの昇順。同時刻は元の順番を維持。重複レコードも保存可能 | はい：再生対象 |
| Comments[].MediaSeconds | 必須の有限な非負数。動画の再生位置0からの秒。小数秒を許可。vposの改名ではない | はい：表示時刻の基準 |
| Comments[].Text | 必須の文字列。chat要素の元の本文。空文字、改行、タブ、前後の空白も保持 | はい：本文。改行を再現 |
| Comments[].Attributes | 必須のオブジェクト。元のchat要素の全属性を、属性名→文字列値で保存。属性なしは空オブジェクト。数字に見える値も文字列のまま | はい：下記の属性を参照。その他も保持 |
| Attributes.date | 元の投稿日時（Unix秒）の文字列 | 再生時はいいえ。EncoderがMediaSeconds算出に使用 |
| Attributes.date_usec | 元の小数秒（マイクロ秒）の文字列。欠落時は時刻計算上0。元のゼロ埋めも保持 | 再生時はいいえ。EncoderがMediaSeconds算出に使用 |
| Attributes.mail | 元のコマンド文字列。順序・空白・未知のコマンドも保持 | 一部：ue／shita／naka、big／small／medium、対応色を解釈。コマンド文字列自体は表示しない |
| Attributes.user_id | 元の投稿者ID文字列。匿名化済みIDもそのまま。匿名化・削除・数値変換を加えない | はい：NG ID、設定画面のログ一覧 |
| Attributes.deleted | 元の削除フラグ文字列 | はい：値が1のコメントを表示しない |
| Attributes.thread | 元のスレッド識別子 | 格納データ再生時はいいえ |
| Attributes.no | 元のコメント番号。ゼロ埋めも保持 | 格納データ再生時はいいえ |
| Attributes.vpos | 元のスレッド内位置（1/100秒単位）の文字列。動画に合わせて書き換えない | いいえ：再生にはMediaSecondsを使用 |
| Attributes.premium | 元の投稿者種別などの属性値 | いいえ：保持のみ |
| Attributes.anonymity | 元の匿名指定の属性値 | いいえ：保持のみ |
| Attributesのその他の項目 | name、nx_jikkyoなど、入力に存在する属性を名前・値とも保持。上記以外も許可 | いいえ：保持のみ |

Attributes内の項目はすべて入力に存在するものだけを保存し、存在しない属性を補いません。XML名前空間付き属性のキーはXNameの展開名（{名前空間URI}ローカル名）、名前空間宣言も保持します。

保持するのはXMLとして解釈した本文と属性値です。文字参照（&amp;や&#10;など）は実際の文字になります。XML標準の改行・属性値の正規化は行われるため、元XMLのバイト列、引用符、属性順、CDATAの書き方までの復元を保証する形式ではありません。NicoJKのchat以外の要素やログの制御行は対象外です。

Encoderは録画範囲のchatを読み、出力動画の時間範囲にあるレコードを保存します。空本文、削除済み、スラッシュで始まる運営コマンド、長い本文、重複レコードもデータとして保持します。dateがない・不正、date_usecが0～999999の整数でない、不正なXML、chat内の子要素がある場合は同期または値の保持を保証できないため除外し、件数を終了時の警告に出します。元の属性値を丸めたり書き換えたりはしません。

NicoBEの表示処理は、deleted=1、空白だけの本文、先頭の空白を除いた本文が/で始まる運営コマンド、1,000 UTF-16コード単位を超える本文を表示しません。この制限は表示側の方針であり、保存形式の文字数制限ではありません。本文の改行は行として表示し、mail中の未対応コマンド（フォント・透明度など）は表示に適用しません。未知のコマンドを本文へ付け足すこともありません。保存済みの本文・属性は変更しません。

#### 同期時刻

MediaSecondsは、元コメントのdate＋date_usec/1,000,000と、出力動画の再生位置0に対応するUTC日時との差です。EncoderはTSの放送時刻・PCRと入出力の先頭映像PTSを使ってこの基準を求めます。date／date_usec／vposは元の値のままです。

MP4を読む側はMediaSecondsだけで同期できます。UTC日時、放送局、元TS、外部ログ、録画情報ボックスを再計算のために要求しません。時間調整・速度・フォント・文字サイズ・NG設定はNicoBE側で再生時に適用します。

### 録画情報JSON

こちらはコメントを格納しなかった動画を外部NicoJKログと同期するための、独立した任意の情報です。Encoderはコメント保存のオン・オフにかかわらず書き込みます。現在の録画情報Version 1は以下の全項目を必須とします。

| 項目名 | 説明 | NicoBEで参照しているか |
| --- | --- | --- |
| Version | 整数1。コメントJSONのVersionとは独立 | はい：形式確認 |
| PlaybackZeroUtc | 出力動画の再生位置0に対応する日時。RFC 3339形式の文字列。EncoderはUTCを出力 | はい：外部ログ同期 |
| SourceStartUtc | 元TSの解析で得た開始日時。同じ日時形式 | 外部ログ再生にはいいえ。元の同期情報の記録 |
| ServiceId | 放送サービスID。正の整数 | はい：外部ログの局判定 |
| NetworkId | 放送ネットワークID。正の整数 | はい：外部ログの局判定 |
| SourceFileName | 元TSのファイル名だけ。絶対パスは保存しない | 再生時はいいえ |
| DurationSeconds | 出力動画の長さ（秒）。有限の正数 | はい：外部ログの対象範囲 |
| SourceFirstVideoPts | 元TSの先頭映像フレームPTSを秒にした有限数 | 再生時はいいえ。同期計算の記録 |
| OutputFirstVideoPts | 出力動画の先頭映像フレームPTSを秒にした有限数 | 再生時はいいえ。同期計算の記録 |

### 読み取り・更新・拡張規則

- 未対応Version、必須項目の欠落、null、型違い、不正な時刻順序、JSON内の同名キー重複はエラー。無言で値を補正しません。
- 将来追加された未知のJSON項目は無視して読み取ります。Attributesの未知の項目は元データなので保存対象です。編集する外部ツールは未知のJSON項目も可能な限り保持してください。意味・型の非互換変更はVersionを更新します。
- 同じ種類のUUIDボックスが複数あればエラー。先勝ち・後勝ちにはしません。サイズ超過、ボックス途中の切断、不正gzip／JSONもエラーです。他のUUIDは無視します。
- 新規のEncoder出力に一度だけ追加します。既存ボックスへの追記更新は禁止。末尾までを占有するsize=0ボックスがあるファイルにも追記しません。更新ツールは別の一時ファイルに該当ボックスを置き換えて検証し、完成後に置換してください。
- NicoBEの読み込み上限は、圧縮コメント48 MiB、展開後128 MiB、50万レコード、JSON深さ64、録画情報64 KiB、トップレベル10万ボックスです。ログ読込時は1レコード1,048,576文字が上限です。録画情報のPlaybackZeroUtcは1990～2200年、DurationSecondsは日時型で表現できる終了日時までを受け付けます。実装上の資源制限であり、NicoJK属性の値域を独自定義するものではありません。上限超過はエラーです。
- 投稿者IDその他の元属性と本文を含みます。NG設定は再生時の非表示処理であり、保存データからの削除ではありません。共有するファイルにはこれらも含まれます。
- 他のソフトでの再変換・再多重化でUUIDボックスが失われる場合があります。

JSON Schema、架空データのサンプル、実装リーダーをリポジトリに含めています。コメントSchemaはdocs/mp4-comments.schema.json、録画情報Schemaはdocs/mp4-recording.schema.json、サンプルはdocs/mp4-comments.example.json、リーダーはsrc/NicoBE/Mp4CommentData.csとMp4UuidBox.csです。Schemaだけでは配列の時刻順や重複キー、gzip・MP4の構造までは検証できません。

## 運用・トラブル対応

### エラーの確認・問い合わせ

NicoBEのコメント読み込み・描画の問題はトレイ通知と設定の「診断」で確認できます。診断には起動中の直近20件を保存し、「更新」で再取得、テキスト選択でコピーできます。同じ動画・同じ種類の通知は繰り返さず、複数プレイヤーからも30秒以内に通知を繰り返さないようにします。GPU描画は5秒以上間隔を空けて最大3回の復旧を試みます。安定動作が30秒続くと、次の障害に対する再試行が可能になります。

Encoderは操作タブに処理結果とログの場所を表示します。処理途中でログの読み書きに失敗した場合は、FFmpegを停止してエラーとして扱います。起動時に保存先を作れない場合も、ログ保存の成否にかかわらず画面に原因を表示します。NicoBEの通常ログとEncoderの起動エラーログは、5 MiBを超えると1世代を退避します。

「.NETが必要」という起動エラーにはDesktop Runtime x64を導入してください。DLL不足にはZIP全体の再展開、保存先エラーには表示されたフォルダの権限・空き容量を確認します。配布EXEは未署名です。Windowsの保護機能で止まる場合は、入手元と警告内容を確認してください。

### 更新・アンインストール

更新時はNicoBEをトレイの「終了」で終了し、Encoderも閉じます。新しいZIPを別フォルダへ展開し、設定・ログ・導入済みFFmpeg・出力動画を残して配布ファイルを差し替えます。実行フォルダを移す場合、ポータブル配置のデータも移し、保存済みのFFmpeg・出力先パスを見直してください。スタートアップ登録は新しい場所で再設定します。Program Files配置時のデータ保存先はLocalAppDataのままです。

削除時は「Windows起動時に常駐」をオフにして保存し、両アプリを終了します。必要な設定・動画を退避してからアプリフォルダを削除してください。Program Files配置時の `%LOCALAPPDATA%\NicoBE` は自動削除されません。削除する場合は、ほかの配置とデータを共有していないことを確認してください。

### 検証環境と範囲

開発時のビルド・基本テスト環境はWindows 11 x64（OSビルド26300）です。すべてのWindows・GPU・MPC-BEのバージョン組み合わせを検証したものではありません。録画中TSの末尾延長など、MPC-BE側に依存する制約は各機能の説明を参照してください。

## ソースからのビルド

必要なもの：

- .NET 10 SDK x64。
- Visual StudioまたはBuild Toolsの「C++によるデスクトップ開発」（MSVC x64とWindows SDK）。
- Windows標準のWindows PowerShell 5.1、またはPowerShell 7。配布用バッチは `pwsh.exe` があれば使用し、なければ標準の `powershell.exe` を使用します。

配布バッチは実行中だけコンソールをUTF-8に切り替え、終了時に元のコードページへ戻します。ビルドログもUTF-8で保存します。

バージョン・公開日・更新履歴は、アプリごとの次のファイルで管理します。

- NicoBE：`release/version.txt`
- NicoBE Encoder（GUI／CLI共通）：`release/version_encoder.txt`

どちらも以下の形式で、**新しいバージョンを先頭に追加し、過去の履歴も残します**。先頭行は見出し、更新内容は1項目1行の箇条書きです。

```text
## 1.0.1 (2026-11-10)
- 設定画面を改善。
- コメント表示を修正。

## 1.0.0 (2026-11-09)
- 初回リリース。
```

バージョンは major.minor.patch、日付は yyyy-MM-dd 形式です。各履歴に更新内容を1件以上記載してください。更新内容はプレーンテキストとして表示します。`Directory.Build.props` は各ファイルの先頭のバージョン・公開日を読み、通常ビルド・配布用ビルドの実行ファイル／DLLと「その他」タブに反映します。ファイルの欠落や先頭見出しの形式不正ではビルドを失敗させます。HTML生成時には履歴全体の日付・バージョン重複・新しい順の並び・更新内容の欠落も検証します。

リポジトリ直下で実行します。

```powershell
.\tools\build.ps1
.\tools\build-encoder.ps1
```

`app\NicoBE.exe`、`app-encoder\NicoBE.Encoder.exe`、`app-encoder\NicoBE.Encoder.Cli.exe` が生成されます。EncoderのビルドスクリプトはGUI・CLIをまとめてビルドします。NicoBEのビルドではGPU描画DLLも生成します。ビルドログは `temp/test-results`、キャッシュと一時ファイルは作業フォルダ内に保存します。

検証後は `tools\clean-work.ps1` で、`temp`（`test-results`を含む）、各プロジェクトの `obj`／`bin` を削除できます。実行中のビルド・検証が終わってから実行してください。`-WhatIf` で削除対象を確認できます。実行ファイル、設定、ダウンロード済みFFmpeg、保存済み動画、通常の動作ログは削除しません。生成物は引き続き `.gitignore` で除外します。

ローカルの画像素材はGit管理に含めません。`assets\nicobe.ico` がなくてもビルドでき、その場合は標準アイコンを使います。独自アイコンを使う場合はこのパスへ配置してください。`tools\build-icon.ps1` はローカルの `assets\nicobe-source-white-outline.png` からアイコンを生成する任意の補助スクリプトです。

放送局とNicoJKの対応表は `src/NicoBE/ChannelMap.cs` にあります。ローカルの `channels.json` があればそちらを使い、さらに `nicobe.json` の `channelOverrides` が優先されます。

MKV用DLLは `src/NicoBE.Mkv/runtime` から `app/mkv` にコピーされます。DLL自体の再ビルド方法は [MKV読み取りDLLのREADME](src/NicoBE.Mkv/README.md) を参照してください。

### 配布用ZIPとHTMLの作成

`release\create-release.bat` を実行すると、上記のビルド環境で両アプリをビルドし、`release` に以下のZIPを作成します。同名のZIPは作成完了後に置き換えます。配布用ビルドは `temp/test-results` 内の専用作業フォルダへ出力し、使用中の `app`／`app-encoder` を上書きしません。NicoBEやEncoderを起動したまま作成できます。専用作業フォルダは成功・失敗のどちらでも終了時に削除します。

| ZIP | 展開後の起動パス |
| --- | --- |
| `NicoBE-win-x64.zip` | `NicoBE-win-x64\NicoBE.exe` |
| `NicoBE-Encoder-win-x64.zip` | `NicoBE-Encoder-win-x64\NicoBE.Encoder.exe` と同じフォルダの `NicoBE.Encoder.Cli.exe` |
| `NicoBE-MKV-Source.zip` | MKV用DLLに対応するFFmpeg・zlib・ラッパーのソースと再ビルド手順 |

実行用ZIPには製品名のフォルダが1つあり、その直下にexe、DLL、READMEと `license` フォルダを収めます。NicoBEの `mkv` フォルダには読み取り用DLLとそのライセンス文書が入ります。利用者側には .NET 10 Desktop Runtime x64 が必要です。エンコード用FFmpegはEncoderの「基本設定」から追加できます。NicoBEを公開するときは、対応する `NicoBE-MKV-Source.zip` も同じ配布先に置いてください。

### 最小限の検証

```powershell
& .\app\NicoBE.exe --self-test
```

結果は `logs` に保存します。これは実際のMPC-BEとの連携やGPU表示を確認する試験ではありません。実再生の確認には、自分で用意した録画と対応ログが必要です。テスト用の録画・コメントはリポジトリに含めません。

## 設定・ログ・出力の保存先

開発用ビルドと配布版で同じ仕様を使います。**Program Files／Program Files (x86)配下の場合だけ**、ユーザーごとのLocalAppDataに保存します。それ以外は、従来どおり実行ファイルが置かれたフォルダに保存します。書き込み権限がない任意のフォルダからLocalAppDataへ自動的に切り替えることはありません。

| データ保存先 | 通常の配置 | Program Files配下 |
| --- | --- | --- |
| NicoBE | NicoBE.exeの隣 | `%LOCALAPPDATA%\NicoBE\player` |
| NicoBE Encoder（GUI・CLI） | Encoderの実行ファイルの隣 | `%LOCALAPPDATA%\NicoBE\encoder` |
| ダウンロードしたFFmpeg | Encoderの実行ファイルの隣のffmpeg | `%LOCALAPPDATA%\NicoBE\ffmpeg` |

Program Filesへ本体を配置する操作には管理者権限が必要な場合がありますが、通常の起動・設定保存・FFmpegダウンロードのために管理者として起動する必要はありません。Program Files配下の複数の配置は、同じWindowsユーザーの設定とFFmpegを共有します。配置変更前の設定・FFmpegは自動移動しません。

| 用途 | NicoBE | NicoBE Encoder |
| --- | --- | --- |
| 設定 | データ保存先のnicobe.json | データ保存先のencoder-settings.json |
| 動作ログ | データ保存先のlogs | データ保存先のlogs |
| 一時ファイル | データ保存先のtemp | データ保存先のtemp |
| エンコード出力の初期値 | — | データ保存先のoutput。設定した別の出力先を優先 |
| 任意の局対応表 | データ保存先のchannels.json。なければ実行ファイルの隣 | データ保存先のchannels.json。なければ実行ファイルの隣 |
| MKV読み取り用DLL | 実行ファイルの隣のmkv | — |
| ダウンロードしたエンコード用FFmpeg | — | 上表のFFmpeg保存先 |

アイコン・MKV読み取り用DLLは常に実行ファイル側に置きます。利用者が設定した動画出力先とCLIの `--settings` は優先し、勝手に変更しません。CLIで指定した入力・出力・設定ファイルの相対パスは、上記CLIの規則に従います。

このリポジトリでビルドした場合は、NicoBEが `app\`、Encoderが `app-encoder\` に入ります。設定とログもそれぞれの中に保存します。

ビルド・検証専用の一時ファイルはリポジトリ内のtemp（検証結果はtemp/test-results）／objなどを使用し、アプリの実行時データとは区別します。

## フォルダ構成

```text
src/NicoBE/           常駐、設定、再生同期、コメント解析
src/NicoBE.Mkv/       MKV読み取りDLLのソース、再ビルド手順、配布用DLL
src/NicoBE.Gpu/       ネイティブGPU描画
src/NicoBE.Encoder/   エンコードUI、GUI・CLI共通のFFmpeg制御
src/NicoBE.Encoder.Cli/ コンソール起動、引数・設定読み込み、進捗表示
tools/               ビルド・検証・起動補助スクリプト
release/             配布用ZIPの作成バッチと出力先
NuGet.Config         パッケージ取得設定
Directory.Build.props 両アプリ共通のビルド設定・バージョン・ライセンス文書の埋め込み
release/version.txt NicoBEのバージョン・公開日・更新履歴
release/version_encoder.txt Encoderのバージョン・公開日・更新履歴
src/Website/index.html CSS・JavaScript・画像を内包した説明ページ
license/LICENSE     MITライセンス
license/THIRD-PARTY-NOTICES.txt 利用コンポーネントのライセンス通知
```

`src/Website/index.html` を原本とする配布ページは、同じ階層の `NicoBE-win-x64.zip`、`NicoBE-Encoder-win-x64.zip`、`NicoBE-MKV-Source.zip` へリンクします。リリースバッチは `release/version.txt` と `release/version_encoder.txt` から、各アプリのバージョン・公開日・更新履歴を組み込んだ `release/index.html` も生成します。各ダウンロードボタンの下に、履歴ファイルからバージョン・日付を見出し、変更内容を箇条書きに整えて表示します。約8行分の固定高の枠でスクロールでき、横並びのカードは同じ高さにそろえます。最新のバージョン・日付はアプリ名の右側にも表示します。各アプリのZIPには、それぞれの履歴ファイルを同梱します。公開時は生成されたHTMLと3つのZIPを同じディレクトリへ配置してください。`src/Website/index.html` は編集用テンプレートです。

GA4の測定IDは、Git対象外の `.local/ga4-id.txt` に `G-` で始まるIDを1行で記載します。リリース時に読み込み、ファイルがない・空・形式が不正な場合は警告を出して、計測なしのHTMLを生成します。生成した `release/index.html` もGit対象外です。

ページの公開URLは `https://www.moreread.net/apps/nicobe/index.html` です。正規URL・共有用メタデータ・アプリの構造化データを設定しています。GA4はmoreread.net公開時だけ有効で、ローカル閲覧では読み込みません。ページのSEO・アクセス解析・表示検証の詳細は [docs/web-page.md](docs/web-page.md) を参照してください。

`.build-home` は.NET SDKの初回処理済み情報などをnicobe内に保存するための開発用フォルダです。アプリ実行には不要で、Gitから除外します。`channels.json` は放送局IDと実況局のjk番号を対応付ける任意のローカル設定で、上記の保存先で読み込みます。`Directory.Build.props` はビルドに必要なソース側の設定なので、ルートに置いてGitで管理します。

実行ファイル、導入済みFFmpeg、個人設定、NG設定、ログ、録画・コメント、画像素材、ビルド中間生成物、検証結果は `.gitignore` で除外します。`app`、`app-encoder`、`assets`などのローカルファイルは、ソース公開とは別に配布物を用意する場合に使用します。
