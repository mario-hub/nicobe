# リリース前テスト

リポジトリの `release/test-release.bat` を実行します。どのカレントディレクトリからでも実行できます。Windows PowerShell 5.1に対応し、PowerShell 7があればそちらを使用します。ビルド条件はREADMEを参照してください。

## 自動確認の範囲

| 項目 | 確認内容 |
| --- | --- |
| Encoder追加パラメータ | `encoder-extra-arguments`：引用符・改行、許可項目／管理項目の拒否、重複置換、x264/x265キー統合、CPU両パス、GPU自動切り替えの抑止、JSONとGUIの保持。`cli-arguments`でも設定読み込みを確認 |
| Encoder追加指定の実エンコード | `encoder-extra-arguments-media`：合成TSのCPU 2パスで最大ビットレート・Bフレームなどを指定し、両工程の引数と出力を検査。不正なプリセット指定時にFFmpegの診断が呼び出し元へ届くことも確認 |
| 実行基盤 | 非ゼロ終了、両出力ストリームの排出、タイムアウト。各テストをJob Objectに所属させ、終了時にその子プロセスも回収 |
| ビルド | NicoBE・GPU DLL、Encoder・CLIの隔離Releaseビルド。MKV DLLは既存の配布用DLLを使用 |
| NicoBE | コメント配置・NG・速度継承、ASS認識・サイズ換算、追っかけログ更新、過去ログの模擬通信・キャッシュ、保存先、エラー処理 |
| MP4末尾データ | `player-self`で数字のみの末尾（1／7／105／1024バイト）を許容し、1025バイト・数字以外・途中の不整合・重複UUIDを拒否。追記を拒否した際の元データ不変も確認。`player-playback-lifecycle`で初回読込エラーの「読取失敗」表示を確認 |
| 連携・GUI | 模擬MPC-BEへの制御、コメント表示切り替え、操作パネル、設定反映・初回ガイド・レイアウト |
| GPU | 画面外の描画、カラー絵文字、縁取り・影、不透明度、同期制御、描画リソースの再生成。実画面の滑らかさを測る試験ではない |
| Encoder | 設定保存・復元、ASS書式、コメント形式、模擬ZIPによるFFmpeg導入・不正ZIP拒否、子プロセスの出力失敗、GUIと初回ガイド |
| CLI | 引数、設定内と引数の相対パス、未知の設定・不正値、同名出力、設定を変更しないこと |
| 合成メディア | 4秒の映像・音声と架空の時刻・コメントを生成。H.264、MP4／MKV、コメント有無・外部ASS、コメントなしの警告、二重音声の分離、AV1、HEVC 2パスのCLI実行 |
| Web | 履歴の順序・不正入力・HTMLエスケープ、両アプリのバージョン反映、デスクトップ・モバイル表示、画像・リンク・SEO・GA4の起動条件 |
| 配布物 | リリースと共通のファイル選択・ZIP格納処理で検証用アーカイブを生成。必要DLL・ライセンス・バージョン・内容一致、個人設定やログ、開発環境のパスの混入を検査 |

AV1はCPUと利用可能なGPUで短時間エンコードします。NVENC／QSV／AMFが使えない場合はフォールバックも確認し、そのハードウェアでの実エンコードはSKIPとします。H.264／HEVCの全GPU・画質・パス数の組み合わせを網羅するものではありません。

## 優先回帰テスト

| 一覧の項目名 | 検証内容 |
| --- | --- |
| `player-playback-lifecycle` | A→B→Cと切り替え、A/Bの読み込みをCの表示後に完了させても旧コメント・パネル状態・字幕選択を通知しないこと。キャンセル、監視・タイマー終了、終了前にキューへ入った通知の無効化。同じ動画の2セッションでAPI要求を共有し、片方終了時は継続、最後の終了時は中止すること |
| `player-scene-continuity` | 実際の設定画面の「反映」と模擬ログ取得完了を前後・途中で重ねる。停止中と0.5／1／2.5倍速で、既存コメントのオブジェクト・X/Y位置・移動時計が保持され、不要な再配置や文字計測がないこと。後続コメントも重複しないこと |
| `encoder-interruption` | 実際のCPU 2パスエンコードで、1/2パス目それぞれFFmpegの進捗出力後に中止。子プロセス終了、パス用一時データの削除、未完了動画の保持と通知、既存動画・ASSのハッシュ不変を確認。実FFmpegの非ゼロ終了とログ保存、GUIキューの失敗表示・中止ボタン・操作復帰、CLIの失敗／中止の終了コード（1／130）と標準エラー出力も確認 |
| `release-package` | 両アプリのZIPについてトップフォルダ構造・全エントリ・内容ハッシュ、実行ファイルのバージョンと履歴、MKV DLL／第三者ライセンスを検査。ワークスペース・ユーザープロファイルのパスをASCII／UTF-16表現で検査。ライセンス欠落・個人設定・ログ・パス混入・履歴不一致・重複・ディレクトリ逸脱を意図的に混ぜ、検査が失敗することも確認 |

動画切り替えと取得完了は、合成データ・模擬HTTP・完了タイミングを制御した処理で再現します。実MPC-BEの画面や体感上の停止・ちらつきを判定するテストではありません。エンコード中止テストはFFmpegの入力速度を抑え、短い入力が中止前に完了する競合を避けます。この制限は通常のエンコードには適用しません。CLIの終了コード130はエントリ処理に中止済みトークンを渡して確認し、処理途中の中止・回収はGUIと共通のEncoderJobで検証します。コンソールのCtrl+Cキー入力そのものは手動確認です。配布物検査は秘密情報一般を検出する仕組みではなく、既知の個人用ファイルやローカルパスを対象とします。

## 隔離と出力

- 実行ごとに `temp/test-results/release-test-日時-ID` を作ります。ビルド結果からテストごとに実行ファイルをコピーし、設定もテスト専用に生成します。
- アプリ設定、過去ログキャッシュ、一時データ、コメント、出力動画は専用フォルダ内です。Program Filesの保存先判定は模擬パスで検証し、実際のProgram Filesや利用者のLocalAppDataには書きません。
- 実エンコード用のFFmpeg／ffprobe／同じ場所のDLLはコピーして実行します。既存のEncoder設定は読みません。FFmpegをダウンロードするテストは模擬HTTPです。
- 配布物検証のZIPと不正データは実行フォルダの`packages`内だけに生成します。`release`のZIP・HTMLは変更せず、MKV対応ソースZIPも生成しません。
- 外部過去ログAPIへの通信をテストモードで禁止します。ブラウザは専用プロファイルで起動し、ページからのHTTP／HTTPS要求を遮断します。Webテストは実際のアクセス解析へ送信しません。ビルドのパッケージ復元は既存のビルド環境・NuGet設定に従います。
- これはVMやOSのセキュリティサンドボックスではなく、保存先・入力・通信・対象プロセスを制限するテスト構成です。追加テストもこの制約を守る必要があります。
- 実行中のNicoBE／Encoder／MPC-BEは操作も終了もしません。テストの子プロセスだけをJob Objectで回収します。起動直後からJobへの登録までの短い期間に子を起動しない、既存の専用テスト入口を使ってください。
- `report.html`は一覧、`results.json`は機械処理用、`summary.txt`はテキスト一覧です。テスト別の`process.stdout.log`／`process.stderr.log`、JSON、画面画像も残します。機械固有のパスを含むため、生成物はGit対象外です。
- ログ等を確認した後は、他のビルド・テストが動いていない状態で`tools/clean-work.ps1 -WhatIf`から後片付けを確認できます。

## 判定と省略

| 表示 | 意味 |
| --- | --- |
| PASS | 正常終了し、結果JSONを持つ試験では`passed:true`まで確認 |
| FAIL | 例外・非ゼロ終了・タイムアウト・結果欠落・検証失敗。ログで原因を確認 |
| SKIP / Automatic | 依存ツール・対応GPU不足、ビルド失敗による後続未実施、`-SkipGpu`／`-SkipMedia`指定など |
| SKIP / Manual | 自動実行しない実再生・実機確認。自動テスト合格とは別に確認が必要 |

終了コードは0＝自動テスト全件合格、1＝FAILあり、2＝FAILなし・AutomaticのSKIPありです。ManualのSKIPは終了コードに含みません。ハードウェアが揃わない開発PCでは2になることがあります。公開判断ではスキップ理由と対応する手動確認結果も確認してください。

Node.jsとChrome／EdgeがなければWeb表示を、FFmpegとffprobeがなければメディア確認を省略します。既に起動したテストのエラーを前提不足とみなして自動的にSKIPへ変更することはありません。

## 手動チェックリスト

- MPC-BEへの自動接続、起動直後・動画切り替え・シーク・一時停止・速度変更・速度継承、字幕との重複抑制。
- 同じ動画を含む複数プレイヤー、片方／両方の終了、監視解除、待機時のCPU・RAM・VRAM解放。
- 実際の画面でのコメントの動き、異なるリフレッシュレートの混在、フォーカス、前後関係、操作パネル、設定画面の読みやすさ。
- 必要に応じた過去ログAPIの実通信。自動試験ではサービス稼働や利用制限は確認しない。
- MKVライブラリ変更時の対応ソースからの再ビルド、ライセンス・依存DLL・配布サイズ。最後に完成ZIPを新規環境へ展開して起動確認。一括テストの検証用ZIPと、実際に公開する配布ZIPは別です。

実録画を使用する確認は利用者が別途用意したコピーで行い、結果には使用環境と未実施項目を記録してください。

## 任意のVM実プレイヤー確認

`src/ReleaseTests/VmPlayback` は、展開した配布版の `NicoBE.dll` を参照して実際のポータブルMPC-BEと連携する追加検証です。製品アセンブリを差し替えず、反射で診断用の内部状態を確認します。通常の一括テストからは起動しません。

- ログイン済みの使い捨てVMで実行します。ゲスト内の検証アプリを終了してから開始し、ホストや普段使いのVMでは実行しないでください。
- ホストで `dotnet build src/ReleaseTests/VmPlayback/VmPlayback.csproj -c Release -p:NicoBEAssembly=<配布ZIPから展開したNicoBE.dllの絶対パス> -o <隔離出力先>` を実行します。通常ビルドと同じリポジトリ内の環境変数・NuGet設定を使用してください。
- 生成された `VmPlayback.*` だけを配布版NicoBEの隣へ置きます。専用作業フォルダの `mpc/mpc-be64.exe` とポータブル用INI、`media/first.mp4`・`second.mp4`に65秒以上の合成動画を用意します。ASSは検証プログラムが専用の動画の隣に生成します。
- `VmPlayback.exe <専用作業フォルダ>` をゲストの対話セッションで実行します。既存アプリとは別に起動したプレイヤーだけを対象に、2台の接続、シーク・一時停止、表示設定、速度継承、動画切り替え、個別／同時終了、再接続、描画リソース解放を確認します。実際のクリックや見た目を確認する試験ではありません。
- `playback-result.json`と終了コードを確認します。進行中のJSONを合格扱いせず、`completed:true`・`passed:true`・終了コード0が必要です。待機時の5秒のCPU／メモリ値はVMと検証プロセスを含む参考値です。
- `tools/test-vm-guest.ps1`はVMwareゲスト専用の補助スクリプトです。既定の `C:\nicobe-vm-test` にプライベートランタイムの `dotnet.zip`、アプリ・上記検証ファイル・動画を`player`／`encoder`／`media`へ配置した `payload.zip`、ポータブル版MPC-BEの `mpc.zip`を準備して `-Prepare` で実行すると、初回ウィンドウ・描画・実連携を順に確認します。認証情報をスクリプトやリポジトリに記載しないでください。

VMでの結果を物理GPUや異なるリフレッシュレートのディスプレイの保証に置き換えないでください。プライベートランタイムで動いた場合も、ランタイムインストーラやProgram Filesへの導入・権限確認とは区別します。
